Mint Uptime Exchange

Flags machines that are likely to fail and gets the repair approved and booked before production stops.

The backend works out what a breakdown would cost and gets sign-off from ops and finance. Then it reserves the parts and assigns a technician. Every repair runs through a 14-step workflow saved in the database, and Server-Sent Events push updates to the frontend.

Data
Everything lives in PostgreSQL, from the machines and alerts to the work orders and the audit trail.
Control
Logins use JWTs. Each role's permissions come from the database and get checked on every request.

  • Express
  • Prisma
  • PostgreSQL

  • Vitest

WattWise

Tracks household electricity use and links it to municipal fault reports and technician call-outs.

An Arduino reads the meter and a small Python script sends the readings to a FastAPI service, which saves them in PostgreSQL. Residents, municipal teams and technicians each get their own flow in the API. If the hardware isn't connected, the frontend switches to mock data.

Pipeline
The Python bridge keeps the serial hardware code out of the web API. It just forwards readings over HTTP.
Access
There's a USSD-style flow too, so you can report a fault without a smartphone.
  • Python
  • FastAPI
  • PostgreSQL
  • Arduino
  • React
  • TypeScript

CivicLens AI

Take a photo of something like road damage and it drafts a report for the municipality.

A FastAPI endpoint checks the photo, sends it to Gemini and makes sure the answer matches a Pydantic model. If Gemini fails or isn't set up, the app falls back to demo data and labels it as demo data.

Boundary
Reports are drafts for a person to check. The app doesn't send anything to the municipality itself.
Failure mode
I can still demo it when Gemini is down, and nobody mistakes the fallback data for a real result.
  • Python
  • FastAPI
  • Pydantic
  • Gemini
  • Cloud Run
  • Pytest
