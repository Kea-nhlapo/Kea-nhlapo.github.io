Three hackathon builds, viewed from the backend: where data enters, how decisions are made, and what happens when a dependency fails.

Mint Uptime Exchange

Turns machinery risk into an approved, scheduled repair before production stops.

The backend calculates the financial case, records separate approvals, reserves stock transactionally, matches technicians, and persists a 14-step repair workflow. Server-Sent Events push state changes back to the interface.

Data
PostgreSQL is the source of truth for machines, alerts, approvals, inventory, work orders, and audit history.
Control
JWT authentication and database-loaded permissions enforce role boundaries on every request.

WattWise

Electricity monitoring that connects household usage, municipal faults, and technician dispatch.

Arduino readings pass through a Python bridge into a FastAPI service and PostgreSQL. The API serves separate workflows for residents, municipal teams, and field technicians, while the frontend can fall back to mock data when hardware is unavailable.

Pipeline
A small bridge isolates serial hardware input from the web API and forwards readings over HTTP.
Access
The system includes a USSD-style flow so core reporting does not depend on a smartphone.

  • FastAPI

CivicLens AI

Turns a photo of a public infrastructure problem into a municipal report draft.

A FastAPI endpoint validates the image and context, sends them to Gemini, and requires structured output that matches a Pydantic response model. Invalid model output, missing credentials, and network failures fall back to labelled demo data.

Boundary
The system drafts reports for review. It never claims to submit them to a municipality.
Failure mode
The product remains demonstrable when the model is unavailable, without presenting fallback data as live analysis.
  • Python
  • FastAPI
  • Pydantic
  • Gemini
